# Release checklist

A Vantage release is one addon archive, `vantage-1.2.0-addon.zip`. It holds `addons/vantage/` (the addon) and `LICENSE`, `README.md`, `CHANGELOG.md`, `docs/GUIDE.md` and `docs/INSTALL.md`.

Don't change the version unless the author tells you to release. Keep `vantage/vantage.lua` and the newest changelog heading at the same version.

`.github/workflows/verify.yml` runs on every pull request. It runs the repository check, the Lua fixtures and the Python tests that need no game and no window. Pushing a new `addon.version` to `main`, or a `v` tag for that version, runs it and then `.github/workflows/draft-release.yml`. That workflow drafts a GitHub release with the archive and that version's changelog section. The draft stays private until you publish it. A runner has no game, so the steps below come first.

1. Review the runtime changes and the newest changelog entry.
2. If mechanics data changed, regenerate it from the manifest's pinned revisions with `python tools/export_catalog.py` and compare the output. `tools/README.txt` has the script's arguments. Keep source uncertainty and client-only limits explicit.
3. Set `ASHITA_LIBS` to the game's Ashita `addons/libs` folder. The tests have no default for it.
4. Run `python tests/run.py`. Then run the Python tests from the tests instructions (`python -m unittest discover -s tests -p "test_*.py"`) and `python tools/check_repository.py`. Inspect the real UI previews at ordinary and narrow settings sizes, and check actual pointer interactions. If the look changed, remake the README pictures with `python tests/preview/readme_images.py` and look at each one.
5. Run `python tests/jit_flush_guard.py` and `python tests/benchmark_frame.py --runtime x86`. Both run the addon in a plain x86 LuaJIT (`tests/luajit-x86/luajit.exe`, or `--exe`). Note the frame numbers in `docs/PERFORMANCE.md` when they change.
6. Run `python tools/client_check.py` on the installed `FFXiMain.dll`. It only reads the file. Check that it finds every pattern exactly once.
7. Run `python tools/package.py`. It writes `dist/vantage-VERSION-addon.zip` with a fixed member order and times, and prints its SHA-256. It refuses to build when a runtime file is missing or unexpected, when a module that `vantage.lua` loads is left out, or when a document link points outside the archive. It also refuses when any file holds a line of `tools/private_markers.txt`, a temporary or scratch path, or an absolute user path. It looks for these in plain bytes and in UTF-16LE, in any letter case. The private markers file lists your own Windows user name, email and character names, one per line. `.gitignore` keeps it out of the repository. The archive leaves out caches, tests, tools, fonts made at run time and game data. Inspect the archive anyway. Never include character settings, sound files, game artwork or private paths.
8. To install it on a game folder, run `tools/install_addon.ps1` in Windows PowerShell. The game can be open:

   ```text
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_addon.ps1 -Zip dist\vantage-1.2.0-addon.zip -Sha256 <the printed SHA-256> -Game <game folder>
   ```

   It refuses an archive whose SHA-256 differs. It notes the hash of every file under `config/addons/vantage` (settings, profiles, shared layout and the rest). It moves the current `addons/vantage` to `vantage-addon-backup-<UTC time>` in your Documents folder. You can pass `-BackupParent` to use a folder outside the game folder and on the same drive instead. Then it copies the new addon in and checks every copied file's hash. It also checks that no settings file changed. If anything fails, it puts the backup back. Each folder moves whole or not at all, so an old addon with a file held open stays where it is. A JSON receipt goes beside the backup. It never touches a startup script or the launcher. With the game open, a loaded Vantage keeps its old code until you run `/addon reload vantage` in game. Don't change any setting in game while the install runs. A saved settings file counts as a change and puts the old addon back.
9. Check the build in the game with the [in-game checks](#in-game-checks) below before you call it live-tested. In release notes, say which results you saw in game and which come from offline tests.

`tools/release_files.py` holds the list of runtime files that `package.py` and `check_repository.py` use. `package.py` and `check_repository.py` never commit, push, publish or install anything. `install_addon.ps1` changes only `addons/vantage` in the game folder you pass. None of them change saved settings.

## In-game checks

Run these on a real client after installing the archive. Note what you saw and what you didn't.

1. Run `python tools/client_check.py` on the installed `FFXiMain.dll`. It finds every pattern exactly once.
2. Install with `tools/install_addon.ps1`, with the game open or closed. Read the receipt. Every copied file matches the archive, and `settings_before` and `settings_after` are the same. The old addon is in the dated backup. With the game open, `/addon reload vantage` loads the new addon.
3. Run `/vg report` and open `reports/latest.json`. `jit.applied` and `clock.available` are both true. `item_recasts` says on or not loaded yet. In a party, `native_party.geometry` follows the game party list. `performance` has frame timings.
4. Cast or receive a few buffs on yourself. Self buffs and Self debuffs count down and match the game's own buff timers. An effect with no known time shows with no countdown, in its normal look.
5. Use one enchanted item with charges. Its recast shows on Item recasts and counts down. If the Recasts panel says item recasts are off, note why.
6. In a party, then an alliance, turn **Your party**, **Alliance 1** and **Alliance 2** on and off on the **Show** tab of Party list buffs. Each switch shows or hides only its own group. Alliance rows show only the effects Vantage saw land on those members.
7. Open the Treasure Pool. Vantage doesn't draw the party list buffs while it's open, and they come back when it closes.
8. Right-click, then double-click, one of your own buffs on a Vantage panel. The buff stays, and nothing comes from Vantage.
9. With the displays locked, hold Shift and drag. Nothing moves. Unlock, then Shift-drag a panel and a group in a panel of its own. They move and keep their new place after a reload.
10. Change the game's resolution, and alt-tab out of and back into fullscreen. Icons and client artwork come back.
11. Run `/addon unload vantage`, then `/addon load vantage`. Everything comes back as it was.
12. Turn on overhead icons with `/vg overhead on`. Target a Hume or an Elvaan, a Tarutaru and a Galka player (yourself or someone else) and run `/vg overhead calibrate` on each. Each time, the second line says the camera is read at scene and in use. It also says X,Z,Y is within 60 yalms and the head sits a positive number of pixels above the feet. If it says the frame had too few scenes, run `/vg set overhead.camera.capture present` and note it. That setting reads the camera at present instead. `/vg overhead preview` puts a sample block over your own head. Up close and from about 20 yalms, the sample block and those players' blocks sit the gap (3 px on a display 1080 high) over the game's name. On your target, the block also sits the gap over its target cursor. The blocks never touch either, and they hold still as the camera turns. In the report's `overhead.name_point`, `usable` is true and every unit row says `path` `name point`. Its `check` puts Vantage within about a pixel of the client's cameras.

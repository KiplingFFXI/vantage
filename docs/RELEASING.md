# Release checklist

A Vantage release is one addon archive, `vantage-1.4.0-addon.zip`. It holds `addons/vantage/` (the addon) and `LICENSE`, `README.md`, `CHANGELOG.md`, `docs/GUIDE.md` and `docs/INSTALL.md`.

Don't change the version unless the author tells you to release. Keep `vantage/vantage.lua` and the newest changelog heading at the same version.

`.github/workflows/verify.yml` runs on every pull request. It runs the repository check, the Lua fixtures and the Python tests that need no game and no window. Pushing a new `addon.version` to `main`, or a `v` tag for that version, runs it and then `.github/workflows/draft-release.yml`. That workflow drafts a GitHub release with the archive and that version's changelog section. The notes end with a hidden line that names the commit the archive was built from, so leave it in when you edit them. If the version already has a release, the run fails unless that release was built from the run's commit and, for a tag, from where the tag points. Then delete that release and run it again, or change the version. If you swap the archive by hand, put its commit in that line. The draft stays private until you publish it. A runner has no game, so the steps below come first.

1. Review the runtime changes and the newest changelog entry.
2. If mechanics data changed, regenerate it from the manifest's pinned revisions with `python tools/export_catalog.py` and compare the output. `tools/README.txt` has the script's arguments. Keep source uncertainty and client-only limits explicit.
3. Set `ASHITA_LIBS` to the game's Ashita `addons/libs` folder. The tests have no default for it.
4. Run `python tests/run.py`. Then run the Python tests from the tests instructions (`python -m unittest discover -s tests -p "test_*.py"`) and `python tools/check_repository.py`. The repository check also refuses any public file, tests and tools included, that holds a line of `tools/private_markers.txt`. CI has no marker file, so only your own run can catch that. Inspect the real UI previews at ordinary and narrow settings sizes, and check actual pointer interactions. If the look changed, remake the README pictures with `python tests/preview/readme_images.py` and look at each one.
5. Run `python tests/jit_flush_guard.py` and `python tests/benchmark_frame.py --runtime x86`. Both run the addon in a plain x86 LuaJIT (`tests/luajit-x86/luajit.exe`, or `--exe`). Note the frame numbers in `docs/PERFORMANCE.md` when they change.
6. Run `python tools/client_check.py` on the installed `FFXiMain.dll`. It decodes the DLL with the research decoder in `research/native-solo-research`, or in the folder `VANTAGE_RESEARCH` names (see `tools/README.txt`). It only reads the file. Check that it finds every pattern exactly once.
7. Run `python tools/package.py`. It writes `dist/vantage-VERSION-addon.zip` with a fixed member order and times, and prints its SHA-256. `python tools/package.py --help` says what it holds, leaves out and refuses. Inspect the archive anyway. Never include character settings, sound files, game artwork or private paths.
8. To install it on a game folder, run `tools/install_addon.ps1` in Windows PowerShell. The game can be open:

   ```text
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_addon.ps1 -Zip dist\vantage-1.4.0-addon.zip -Sha256 <the printed SHA-256> -Game <game folder>
   ```

   `Get-Help tools\install_addon.ps1 -Full` says what it checks, where the backup goes and what it does on a failure. With the game open, run `/addon reload vantage` in game right after the install, before you open `/vg`. Until then a loaded Vantage can load some of the new files, such as the settings window's pages, into its old code. Don't change any setting in game while the install runs. A saved settings file counts as a change and puts the old addon back. Read the receipt. Every copied file matches the archive, `settings_before` and `settings_after` are the same, and the old addon is in the dated backup.
9. Check the build in the game with the [in-game checks](#in-game-checks) below before you call it live-tested. In release notes, say which results you saw in game and which come from offline tests.

`tools/release_files.py` holds the list of runtime files that `package.py` and `check_repository.py` use. `package.py` and `check_repository.py` never commit, push, publish or install anything. `install_addon.ps1` changes only `addons/vantage` in the game folder you pass. None of them change saved settings.

## In-game checks

Run these on a real client after installing the archive. Note what you saw and what you didn't.

For a quick run, steps 1 to 9 are the smoke list: the report, Self buffs, item recasts, the party groups, the Treasure Pool, the no-cancel click, locking, a resolution change and an unload and load. A release also runs every step that `git diff v<last release> -- docs/RELEASING.md` adds or changes, apart from steps where only the number or a step number they point at changed.

### Before you start

1. Run `/vg report` and open `reports/latest.json`. `jit.applied` and `clock.available` are both true. `item_recasts` says on or not loaded yet. In a party, `native_party.geometry` follows the game party list. `performance` has frame timings. The paths under `art` start from `<game>` or `<Ashita>`, and your Windows user name isn't anywhere in the file.
2. Cast or receive a few buffs on yourself. Self buffs and Self debuffs count down and match the game's own buff timers. An effect with no known time shows with no countdown, in its normal look.
3. Use one enchanted item with charges. Its recast shows on Item recasts and counts down. If the Recasts panel says item recasts are off, note why.
4. In a party, then an alliance, turn **Your party**, **Alliance 1** and **Alliance 2** on and off under **Groups** on the **Show** tab of Party list. Each switch shows or hides only its own group. Alliance rows show only the effects Vantage saw land on those members.
5. Open the Treasure Pool. Vantage doesn't draw Party list while it's open, and it comes back when it closes.
6. Right-click, then double-click, one of your own buffs on a Vantage panel. The buff stays, and nothing comes from Vantage.
7. With the displays locked, hold Shift and drag. Nothing moves. Unlock, then Shift-drag a panel and a group in a panel of its own. They move and keep their new place after a reload.
8. Change the game's resolution, and alt-tab out of and back into fullscreen. Icons and client artwork come back.
9. Run `/addon unload vantage`, then `/addon load vantage`. Everything comes back as it was.
